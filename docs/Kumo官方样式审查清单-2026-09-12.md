# DDYIDC Kumo 官方样式审查清单

- 审查日期：2026-09-12
- 审查基线：`@cloudflare/kumo` 2.13.1（项目声明 `^2.12.0`）
- 官方依据：Kumo 官网组件文档、Sidebar / Accessibility / Colors / Installation 页面、随包 CLI 的 48 项组件注册表与组件文档
- 代码范围：`src/apps/{portal,console,admin,sales}`、共享布局和组件、路由出口、全局样式

## 结论

Console、Admin、Sales 的全部侧栏页面共用 `DashboardLayout`，现已统一由 Kumo `Sidebar.Provider`、`Sidebar`、`Sidebar.Header`、`Sidebar.Content`、`Sidebar.Menu`、`Sidebar.MenuButton`、`Sidebar.Footer`、`Sidebar.Trigger` 和移动端 `Sidebar.MobileTrigger` 渲染。菜单数据、分组、权限过滤、激活判断和路由目标没有改变。Portal 入口的既有信息架构是顶部导航，不存在左侧菜单，不应为了形式一致而改成 Sidebar。

审查发现的可无歧义对齐项已完成；保留两项需要品牌或接口契约决策的事项，没有擅自修改业务含义。

| 位置 / 页面 | 审查前现状 | Kumo 官方规范 | 处理建议 / 结果 |

| Portal | 顶部公共导航，无左侧菜单 | Sidebar 用于存在左侧信息架构的应用壳，不应凭空改变导航模型 | **保持**：继续使用 Kumo Surface / Link / Button；不改变 Portal 功能与信息架构 |

| 通用表格行 | 额外叠加自定义 hover 背景 | `Table.Row` 自带官方悬停、选中和语义 | **已修复**：移除重复 hover 覆盖 |

| 注册页、客户编辑手机号 | 用 InputGroup 强行组合 Select / Input，并覆盖圆角、阴影和边框 | 不覆盖组件内部视觉；Select 和 Input 各自保留完整标签、焦点和校验行为 | **已修复**：改为响应式网格中的独立 Kumo Select + Input |
| Button / Input / Select / Textarea / Dialog / Table / Tabs / Pagination / Badge / Switch / Card / Chart | 大多数页面已采用 Kumo 组件 | 优先使用 Kumo 高层组件和语义 token，不复制其颜色、圆角、阴影或 focus 样式 | **已确认合规**：全量检索未发现自定义通用按钮、输入、选择框、文本域，也未发现 raw 调色板、`dark:` 覆盖、任意圆角/阴影或内联视觉样式 |

| 工单附件选择 | 隐藏原生 file input，由 Kumo Button 触发 | Kumo 当前注册表无 FilePicker | **保持**：原生 input 仅承担文件选择能力，视觉入口仍为 Kumo Button |

| 工单状态颜色 | 后端配置仍以 `#cc0000` 等十六进制业务数据返回，前端映射为语义 Badge variant | 视觉层使用语义状态 token，不应直接渲染任意颜色 | **已隔离 / 需业务确认**：前端没有把十六进制写入 CSS；若彻底移除该数据契约，需要后端将颜色字段迁移为语义状态枚举 |
| 侧栏品牌标识 | “D” 字标使用 `text-kumo-brand`，但没有正式品牌资产 | 颜色必须用 Kumo token；品牌图形内容由业务品牌规范决定 | **需业务确认**：现有视觉已合规；是否换正式 Logo 需提供品牌资产和暗色版规则 |
| 构建分包 | Vite 对约 600KB 的少数异步 chunk 给出体积提示 | 与 Kumo 视觉对齐无直接关系 | **建议后续性能任务**：不在本次 UI 范围内改动加载策略，避免改变业务模块边界 |
