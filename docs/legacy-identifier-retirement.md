# 旧客户 ID 退役：本地候选

发布候选：后端 v0.1.163、前端 v0.1.196。仅兼容读取与显示修复，保留旧表；生产安装由用户手动执行，生产迁移和删表需另行确认。

## 契约

客户现版本 ID 全程按字符串返回和显示；充值列表及详情不再显示旧迁移用户名。客户列表、会话标签、订单、待办、域名、积分、CDN、拼团及上下游订单的相关客户显示同步处理。数据库用户名、登录凭据、密码升级、客户归属及收益不改写，实际供应商账号/机器登录名/外部交易号不改写。

历史 GET 路径 `/api/v1/console/history/orders`、`/records`、`/ticket` 保持不变；仍按会话客户隔离、只读、金额元、ID 字符串。`internal/historyarchive` 仅在批次 complete 后选择中性归档；未迁移时兼容旧表，不读取半成品。查询失败保留错误，实例权限判断失败保持只读。

离线复制工具 `tools/retire_legacy_ids.py` 仅接受 VM 私有 `/tmp/ddoidc-legacy-retirement-*/mysql.sock`，要求 skip_networking=1、路径不是符号链接。它不支持生产连接、不注册路由/任务、不删旧表、不更新账本、不执行支付或履约。`--apply` 将六类历史数据复制到中性表，逐字段 NULL-safe 比对、核对数量、验证客户及工单父子关系，在同一事务提交数据和批次标记；重复运行只校验，不覆盖差异数据。DDL 可重入但不依赖事务回滚，尚无完成标记时服务继续旧读路径。

| 目标表（system） | 保留内容 |
|---|---|
| history_orders | 现订单ID、客户归属、原订单参考号、状态、金额及支付日期 |
| history_order_items | 现明细ID与订单关联、产品描述、原金额 |
| history_records | 现记录ID、客户、金额余额、现订单/实例关联、工单父子关系、业务内容；移除结构化旧来源引用 |
| instance_migration_metadata | 现实例ID、原金额周期及最终只读确认状态 |
| customer_migration_baselines | 现客户ID、历史可用/冻结余额核对基线和重复手机号标志 |
| identity_evidence | 现归档ID、客户和实名记录关联、原密文及HMAC逐字节保留；不解密改写 |
| history_archive_batches | 本轮离线退役完成标记 |

历史原文与密封实名证据保留，不能把物理清理解释为对历史文本/密文的不可逆洗稿。旧密码兼容密钥与 v10 哈希按原机制保留。现 ID 注册、更新器迁移记录、账本、支付、订单、收益与归属表禁止清理。旧离线 Import/SupplementHistory 在完成标记存在时拒绝重新导入，避免旧表重建或历史履约重放。

## 演练与部署边界

- 主演练使用 VM 已有 2026-10-04 切换备份，真实记录只用于无网络副本读取；与 2026-10-27 生产数量不同，不能代替生产执行前最新快照核对。
- 另有纯合成边界库，覆盖超过 JS 安全整数的客户 ID、跨客户/批次相同旧工单号、归属/收益/密码/资金逐行摘要不变、重复执行、归档篡改拒绝及生产 socket 拒绝。脚本：deploy/linux/tests/test_legacy_retirement.sh。
- 主副本已执行源表加密备份、显式白名单删除、无旧表的历史订单/工单/密码/实例和导入拦截测试，随后恢复源表并再次校验。备份及密钥仅留 VM 私有演练目录，不进入仓库、HTTP目录或交付报告。
- 应用只需新查询表及批次标记 SELECT，不应获得历史归档写权限，密文证据/余额基线不对普通查询身份开放。生产实际运行身份授权、最新快照、导入工具退休与备份恢复演练必须在批准的执行窗口再核验。
- 先安装兼容补丁并确认所有消费者升级，再离线复制/核对并授予所需窄查询权限；旧表在用户单独确认前保留。当前工具故意没有生产连接和删表功能，不能直接拿 VM 删表测试脚本用于生产。
- 不覆盖较早全库备份到有新支付的生产库；表级恢复和写入隔离按批准方案执行。
