# 后台支付设置

入口：后台 → 系统配置 → 支付设置。仅状态有效的超级管理员可读写，现有管理员会话、CSRF和随机后台入口保护保持。

GET /admin/v1/payment/settings 返回普通参数、配置版本、各凭据配置标识和是否待重启，不返回私钥/API密钥/平台公钥原文。PUT 使用相同结构并必填2至255字修改原因，64KiB上限，拒绝未知字段与模拟支付。空凭据保留原值。修改版本过期返回409。

支付宝应用/商户、官方网关、回调与返回地址、私钥和公钥；微信应用/商户、商户证书、回调基地址、APIv3密钥、商户私钥、平台公钥与ID；支付过期分钟数均可配置。验证渠道必要字段、官方支付宝网关、HTTPS/本地开发地址及密钥格式。禁止URL内嵌账号密码或fragment。仅本地格式校验，不会发起真实收款或自动退款。

配置整体AES-GCM加密，存system.system_configs的payment.admin_settings.v1；无新增数据表。与system.todo_audits追加审计同事务，审计只包含原因、开关与是否更换凭据，不保存原文。原payment.expire_minutes行锁串行首次与后续写入，revision避免过期页面覆盖。

保存后安排后端重启生效，页面区分运行中开关和已保存配置。不会自动重启或在请求中切换凭据，避免影响未完成支付。更换商户/凭据须先关闭渠道并重启使停用生效，再处理未完成支付，之后才允许替换。停用仅阻止新支付，保留已配置渠道的验签/查单/关单能力，已支付回调仍走原金额、身份校验与幂等入账。

首次没有后台配置时继续读取原服务器支付宝凭据及数据库微信配置，不复制实际凭据到仓库。修复原支付宝仅凭文件存在启用的行为，明确读取payment.alipay.enabled。保存后台配置后，启动优先加载加密配置，不再依赖旧凭据文件；不能把旧默认值重新覆盖后台配置。

回归：VM go test/vet/build/releasecheck；真实隔离MySQL覆盖开关0/1、加密与脱敏、空凭据保留、重启加载、过期revision、无效配置、未支付阻止换商户及审计失败回滚；普通测试跳过的MySQL场景登记为隔离测试，CI finance recovery实跑。手机390和PC1440共8组模拟API浏览器验收覆盖保存、403、409、校验失败和无横向溢出。未进行真实支付或修改生产凭据。
