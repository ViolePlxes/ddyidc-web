# 供应商商品对接超时与结果确认修复

实际供应商映射按钮和拖动入口调用upstreamProductsApi.create，原来继承全局15秒超时；生产qkidc #488的同时间窗请求15秒客户端499，而后端约33—35秒完成并落库。

## 实现

- create和批量connect单独设置120秒等待，全局请求仍15秒，业务接口与后端不变。
- 共享connectWithConfirmation先读映射；有效映射按supplierId+upstreamProductId、sync、非零productId校验，已存在时刷新，不重复POST。
- 当前页面相同账号/供应商/商品的并发调用复用同一Promise。发送前在localStorage保存pending标记，按管理员ID隔离。
- 网络、超时、408或5xx结果不明时，只读核对至多4次（间隔2秒），发现唯一有效映射就显示已核对成功；不自动重发写请求。
- 持续未知保留标记，以警示色“对接结果待确认”展示，按钮转为“核对对接结果”。刷新后仍仅核对；明确业务拒绝清除标记。已确认成功也清除标记。
- 若持续没有映射，不能仅据空列表断定旧请求未执行。维护人员须确认后台请求已经结束且没有落库，才可清理该账号/供应商/商品的浏览器pending标记后重新对接。该标记是浏览器重试保护，不是后端分布式锁，不替代服务端事务/幂等。

## 验证

scripts/upstream-connect.test.mjs九项回归纳入release-validation CI，覆盖正常/已存在/晚提交/持续未知/明确拒绝/并发/读取或存储故障/错供应商与未发布/重复关联。VM真实页面和XHR进行超过15秒慢响应、断网晚完成及刷新核对的隔离验收；不使用生产写操作。

前端候选v0.1.162，后端保持v0.1.129；最终SHA、生产在线更新和只读验收见系统开发地图与发布报告。生产#488已成功关联，本轮不得再次对接来测试。
